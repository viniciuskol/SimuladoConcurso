# study/data — invariantes

- `questions.json` só contém questões com `verification.agree: true`. A regra é `confidence: "high"`; as 10 questões antigas com `"medium"` aparecem no app com aviso. Nunca escrever uma entrada aqui sem passar pelo processo de verificação (ver plano em `~/.claude/plans/vou-fazer-um-concurso-compiled-wreath.md`, seção F).
- Divergências entre a resposta re-derivada e o gabarito impresso vão para `study/_internal/review-queue.json`, nunca direto para `questions.json`.
- `areas.json` é a fonte única da taxonomia: 8 áreas técnicas do Anexo IV do Edital nº 04/2026, Ênfase 5 (Conhecimentos Específicos, 50 questões) + 2 áreas de Conhecimentos Gerais/Básicos comuns a todas as ênfases (`portugues`, `ingles` — 10+10 questões, ver `sourceNote` de cada uma). Os `id`s são estáveis — não renomear, só ajustar `label`/`topics` se necessário. Por decisão explícita do usuário em 2026-08-21, Português/Inglês foram incluídos no app mesmo sendo de uma fase de prova separada (Conhecimentos Gerais) — provas já processadas antes dessa decisão (prova_6, exame 2018) devem ser reprocessadas para recuperar essas questões que haviam sido descartadas.
- `content/<area-id>.json` só deve citar como `patterns[].evidence` questões que já existem em `questions.json`.
- Questões cujo enunciado depende de um texto-base compartilhado (ex.: "Segundo o Texto I...", "In Text I...", questões de compreensão de texto em `portugues`/`ingles`, ou qualquer questão de Conhecimentos Específicos que remeta a um texto/caso apresentado antes do bloco de questões) DEVEM ter o campo opcional `passage` (string HTML, mesma convenção de `stem` — pode ter múltiplos parágrafos e rótulos como "Texto I"/"Texto II"). Repetir o mesmo `passage` em todas as questões que dependem dele é o comportamento esperado (não é duplicação indevida) — a UI deve sempre mostrar o texto-base antes do enunciado, mesmo quando a questão anterior já mostrou o mesmo texto.
- Questões com figura ou tabela da prova original têm `images: [{ "src", "alt" }]`, com os recortes em `data/figures/`. O enunciado marca a posição de cada uma com `[[fig:N]]` (N começa em 1). `alt` descreve a figura para leitor de tela e não entra na tela da questão. `minWidth` (opcional, em px) marca figura larga: ela rola para os lados no celular em vez de encolher até ficar ilegível.
